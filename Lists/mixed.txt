# ============================================================================
# 自定义混合名单 —— 手动维护
# ============================================================================
#
# 用途：在同一个文件里同时写「要拦截」和「要放行」的域名。
#       本文件参与全部四个版本（Full / Pro / Lite / Slim）的构建。
#
# 格式：靠前缀区分黑白，两种都支持
#
# 规则说明：
#     - 以 ! 或 # 开头的行视为注释，空行忽略
#     - 大小写不敏感，会自动转为小写
#     - **裸域名一律按「拦截」处理**，要放行必须显式写 @@ 前缀
#
# 冲突优先级（从高到低）：
#     1. Lists/whitelist.txt        手写白名单
#     2. 本文件的 @@ 放行条目
#     3. Lists/blocklist.txt        手写拦截名单
#     4. 本文件的拦截条目
#     5. 上游源
#   即：放行一律优先于拦截；若同一域名在本文件内既写放行又写拦截，放行生效。
#
# 与另两个文件的关系：
#     - Lists/whitelist.txt  只放行（无需 @@ 前缀）
#     - Lists/blocklist.txt  只拦截（无需 || 前缀）
#     - 本文件               两者混写（需用 @@ 前缀表示放行）
#   三个文件最终合并处理，效果等价于把它们按上述优先级叠加。
#
# 生效方式：提交本文件后，GitHub Actions 会在下次运行时自动纳入。
# ============================================================================
